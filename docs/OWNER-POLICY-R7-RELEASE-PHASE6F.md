# Phase 6F — controlled activation of the first exact local DENY editor

Source candidate only. No production release or permission change performed.

The existing owner-only release configuration accepts one optional top-level key: "ownerLocalDeny": "SONAR_ACCEPT_ISSUE_V1". Preserve the existing schemaVersion and providers exactly. The runtime requires a valid release nonce; the existing activation gate blocks owner POSTs before owner activation. No new credential, mount, Windows controller or environment override is introduced. Config without the key keeps IncidentCore; attempting to start it against local-policy SQLite tables fails closed. First activation requires explicit owner-reviewed config; ordinary Auto inherits existing config and does not introduce the new key.

Only native Sonar accept_issue is editable, with a literal existing ASK/ALLOW and exact issue target. READ, GitHub, workspace, extension and PowerShell editing are out of scope. The R7 server composes LocalDenyCore, owner portal and broker before binding listeners. The change descriptor includes installed package source, loaded Sonar/machine credential identity and registered owner public-key generation. Owner credential generation and expiry are rechecked after WebAuthn before CAS. This is in-process identity, not independent host attestation.

The release state helpers check and seal the three local policy tables (revision, DENY rows, audit events). Allowed append-only UNCERTAIN growth cannot change their digest. Initial installation initializes the tables on the staged clone, not retained source. Historic requests are not rewritten. Existing UC-GW-005 manual bound Check -Build -SourceSha and Apply -Image plus -CheckedImageRecord are required for the first activation, with the same reviewed complete public config, probes, preservation scopes and worker quiescence. Subsequent Auto may inherit the protected Complete record. Existing Check image/state binding, Backup and Promote remain mandatory.

Before activation, owner must verify retained previous image and state, exact Windows controller/source SHA, independent worker quiescence, single admitted active state volume and credential identity. Verify unaffected Sonar READ, exact denied issue proposal without provider effect, unchanged ASK for another issue, owner-only WebAuthn, persisted receipt, and restart using the same guarded config. Do not create an external WRITE merely to test denial. Failed or unknown Apply follows UC-GW-006 with original attempt.

Old images or restoring a pre-DENY database can resurrect ASK. Independent monotonic history is deferred. Do not automatically Return to pre-DENY policy state after a confirmed DENY; preserve current state and reconcile events. Deliberate restore requires owner acceptance and reestablishment of restrictions before machine access. No independent rollback guarantee, DENY removal, ASK/ALLOW editor or Dynamic Windows policy is implemented.

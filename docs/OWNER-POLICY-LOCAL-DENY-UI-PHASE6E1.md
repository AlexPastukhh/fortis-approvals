# Phase 6E.1 — opt-in owner Dashboard exact local DENY (source only)

**2026-11-21: SOURCE CANDIDATE, NOT DEPLOYED.** Phase 6C.8 merged in PR #179. The existing R7 server does not select the local policy Core; this PR neither changes that decision nor authorizes a release.

The existing read-only inventory and inactive draft-review controls remain separate. The new panel in API и политики is hidden by default. It appears only when the owner session obtains the exact DENY-only capabilities from the Phase 6C.2 portal and a matching local-policy inventory revision. The browser permits selecting an active literal native ASK/ALLOW exact row or actor-scoped row (one explicit target). No generic policy apply endpoint, global rule, extension policy, callable, ALLOW grant, DENY removal or PowerShell bypass is added.

The owner first prepares a target-exact descriptor through the existing owner-only begin endpoint; the panel displays actor, provider, operation, target, old and new policy, configured scope, revision and request UUID. This does not commit. Separate confirmation uses the fresh required-UV WebAuthn request and sends finish exactly once with the original descriptor and CSRF. A changed target, selection, session, inventory reload or departure from the tab invalidates prepared UI state. The server remains the authority for session, Host/Origin, challenge, revision and CAS. No browser state is an authorization.

On an ambiguous finish response, the page retains the original UUID in memory and blocks further attempts until readback confirms the original local audit record. A missing record is not proof of no effect. No automatic retry. Copy the UUID before closing/reloading the browser; this in-memory UI marker is not a durable audit log or proof of rollback protection. On success refresh the inventory; the UI does not claim all workers enforce the denial.

Acceptance: eight isolated Node VM tests of browser logic, plus existing owner HTTP, real VirtualKey/FIDO2 and Core tests in Source CI. These are not a live owner-browser acceptance test. Default R7 still has no active local-deny endpoint. Owner-host topology and source/credential identity, migration, safe restoration and all-worker enforcement remain STOP conditions; the owner deferred the independent immutable history. Production release and actual activation require separate owner-controlled work.

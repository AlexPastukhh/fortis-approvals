# P1 Phase 3 — inactive versioned policy draft ledger (source only)

**Status:** PR source candidate, 2026-11-19; no live or deployed policy editor.

## Scope

`fortis_approvals.extensions.owner_policy_draft_ledger.PolicyDraftLedger` is a private durable SQLite storage component for **inactive proposals**. No import, initialization, route or overlay to `Core`, `ExtensionRuntime`, Owner Portal or machine ingress exists. This is not a new authorization source, not an AI write API, not a WebAuthn shortcut, and not an owner grant effect. A staged `ALLOW` for `powershell.execute` **does not** change the real executor's `ASK` or bypass Dynamic ASK; it remains an inert draft.

Input: trusted exact `(actor, provider, operation, target)` baseline of literal `DENY/ASK/ALLOW` rules, bound to 64-hex source digest, 64-hex credential-generation digest, and policy version. Unknown rows, malformed values, scope expansion or callable policy predicates are rejected. Private parent directory, private `0600` database, symlink and hard-link checks reduce accidental exposure; this SQLite is intended for a **trusted protected host path**, not the shared Repo workspace or machine-readable credentials. This candidate does not create or provision any production database.

- `snapshot()` and bounded `audit_history(after_revision, limit)` independently verify the baseline, current projection, sequential revisions, immutable canonical event contents and SHA-256 audit hash chain. Reports `canApply=false` and `runtimeIntegration=NOT_CONNECTED` on every read.
- `stage_draft(...)` atomically checks exact expected global revision, expected current draft policy, source digest, credential-generation digest and policy version inside `BEGIN IMMEDIATE`; writes only draft state and a canonical audit event. Repeating an identical UUID returns readback, conflicting replay fails closed, concurrent stale CAS fails closed. Reason is a bounded **code**, not free-form secrets.
- `rollback_draft(...)` atomically records a new revision restoring **the draft to its trusted baseline**; it does **not** revoke, override or roll back an active Core rule.
- Reopening a durable store preserves revisions and history; a changed baseline/configuration is **denied** until an explicit reviewed migration. Store fails closed on corrupted projection/event hash or mismatched source pins.

**Audit limitation:** the unkeyed hash chain detects accidental or partial modification and inconsistent projections; it is **not** an anti-tamper signature against an attacker who can rewrite all SQLite rows. Runtime protection and independently anchored audit receipts are required before this can authorize live grants.

## Deferred security gates — not provided by this change

1. Trusted owner-approved baseline migration and exact active policy overlay semantics, including native/extension predicate precedence, cross-actor and pending/UNCERTAIN request effects, startup/restart invalidation and revocation/credential rotation.
2. Fresh **strong** (not session-only) WebAuthn challenge for each exact permission transition with Owner Portal CSRF/origin/session, source/credential-generation digest and optimistic CAS, one-use proof, audit receipt and expiry.
3. Atomic live Core policy activation, cache invalidation, persistence/rollback of *active* rules, threat review, negative concurrent/multi-process and release/backup/restore E2E. No ability to apply `ALLOW` to an unrestricted PowerShell shell before its own Windows command-policy enforcement and owner acceptance.
4. Explicit owner release through checked source PR/CI and protected image/Windows process. Source merge is not runtime deployment.
